The bug to keep looking at: in the cloud the clump spins faster and faster and gains energy. Measured (scratch probe, 150 bodies, Random at 1 m/s): total angular momentum L stays exactly 2071 until bodies touch, then climbs to 5870 by 30 s at a constant cloud size. Spin at 1 m/s: 20478 to 28455. Cause: particle_collide_spheres pushes the two positions apart without touching the velocities. In a turning clump that moves a body outward at the same sideways speed, so m r x v grows, always along the spin (the change per push is penetration / total inverse mass * n x (v_b - v_a)). The bounce impulse is along the line of centers and cannot change L. Checked: a scratch build without the push keeps L at 2071, but then bodies sink fully into each other and the 1/r^2 pull flings them out, so some separation is needed. The book's ch 7 resolver moves positions the same way.

Plan A, agreed with me: separate with velocity instead of position, an extra impulse along the normal scaled by the overlap (bias speed ~ beta * penetration / dt). An impulse along the line of centers cannot change momentum or L, so the spin up should go away. It lives in the engine: phys/collide.c gets a second function next to the old one (proposed name particle_collide_spheres_soft, ask me if the name is fine). The cloud uses it first. Then measure L, overlap and jitter headless and let me look in Chrome. Then try the balls on it: if the pile stays still the old function goes, else keep both and write down why. Things to decide with me as we go: beta, whether a small position push (slop) stays, how it plays with the rest speed rule (PHYS_REST_SPEED), and that the bias adds a little energy (may look springy). Note: a split impulse (pseudo velocity used only to move positions) is still a position push, so it would not fix L. Rejected for now: plan B, keep the push and add a sideways friction that cancels the L it adds.
